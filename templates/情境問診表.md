# 情境問診表

> 先推斷、再問。對話裡已經有的資訊直接填進「答」欄；只把真正空著的格子拿去問使用者，一次問完，最多 8 題。
> 問診的目的不是蒐集資料，是決定三件事：**選哪個架構、用哪套題庫、跑 draft 還是 review**。

## 問診表

| # | 面向 | 問 | 這題決定什麼 | 答 |
|---|---|---|---|---|
| 1 | Who | 評審是誰？人數、背景（業界／學界／投資人／外籍／校方），知道名字就寫 | 評審原型 → Q&A 題庫；語言深度 |  |
| 2 | Why | 評審聽完要做什麼決定？（選你去交流／投資／打分數／採用） | 一句話主張的靶心；用因果邏輯還是效果邏輯說服 |  |
| 3 | What | 你的一句話主張是什麼？（評審離場只記得這一句） | 所有段落與投影片都服務它；答不出來就先做主張打磨 |  |
| 4 | When | 時限幾分鐘？有無 Q&A、幾分鐘？比賽日期？ | 架構選型（3 分鐘和 10 分鐘用的架構不同）；排練天數 |  |
| 5 | Where | 場地與設備：投影比例、有無簡報筆、麥克風、能否走動 | 上台前檢查清單；肢體規劃 |  |
| 6 | How | 語言（中／英／混）？投影片頁數或格式限制？可否用動畫、影片？ | 語速門檻；頁數上限；視覺類型選單 |  |
| 7 | How much | 評分表有公開嗎？各項權重？必答題（例如商業模式、團隊）？ | 對齊評量表；把必答題排進段落 |  |
| 8 | 現況 | 已有草稿或投影片嗎？貼上或給路徑。曾被誰給過什麼回饋？ | draft 或 review 模式；review 從既有稿的弱項切入 |  |

## 問診後的第一個檢查點

用三句話向使用者複述：「你要說服（誰）做（什麼決定），核心主張是（一句話），我打算用（架構）在（時限）內講完。」對了才往下走。
